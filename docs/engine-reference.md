# Engine Reference — formulas, step formats, and the Boolean subset

Everything the UI shows is computed by the pure TypeScript modules in
`src/engines/` (plus `src/lib/` helpers). This page documents exactly what
each engine does: the formulas, the shape of every step record the views
render, and the honest limits. If a number appears in the app, one of these
modules produced it — nothing is hardcoded in a component (spec §36).

All engines are React-free and fully unit-tested (`tests/*.test.ts`).

---

## 1. Logic gates — `src/engines/logic.ts`

Seven gates, each a pure `(a: Bit, b: Bit) => Bit` function plus its truth
table, Boolean expression, IC number, and a teacher-voice explanation.

| Gate | Rule | Expression | IC | Notes |
| --- | --- | --- | --- | --- |
| AND | 1 only if both are 1 | `Y = A . B` | 7408 | two switches in series |
| OR | 1 if at least one is 1 | `Y = A + B` | 7432 | two switches in parallel |
| NOT | flips its single input | `Y = A'` | 7404 | bubble on a triangle |
| NAND | AND then invert | `Y = (A . B)'` | 7400 | universal gate |
| NOR | OR then invert | `Y = (A + B)'` | 7402 | universal gate |
| XOR | 1 when inputs differ | `Y = A ⊕ B` | 7486 | SUM bit of a half-adder |
| XNOR | 1 when inputs equal | `Y = (A ⊕ B)'` | 74266 | equality checker |

- Truth tables (`truthTable(gate)`) come in counting order with A as the
  more significant bit: 00, 01, 10, 11 (two rows for NOT).
- The logic page adds a fixed 260 ms propagation delay for the signal
  animation; the engine itself is instant. Reduced-motion users get the
  value immediately.
- Syllabus anchor on every gate: SSC/HSC ICT Chapter 3 — Number Systems and
  Digital Devices.

## 2. Boolean expressions — `src/engines/boolean.ts`

Tokenizer → recursive-descent parser → evaluator → truth table, with
teaching-quality errors (`BooleanParseError` carries a `kind` and the 0-based
`position` of the offending character).

### Operator table (what students can type)

| Operation | Symbols / words | Notes |
| --- | --- | --- |
| AND | `.`  `*`  `&&`  `and` | highest binding of the binary ops |
| OR | `+`  `|`  `||`  `or` | lowest binding |
| XOR | `^`  `xor` | between AND and OR |
| NOT | `!`  `~`  `not` (prefix) or `'` (postfix) | `A'`, `(A+B)'` both work |
| Grouping | `( )` | overrides precedence |
| Constants | `0`  `1` | |
| Variables | `A`–`Z`, optionally with digits (`X1`) | max **4** distinct variables |

**Precedence:** `NOT > AND > XOR > OR`. The overline (bar) notation cannot
be typed — write `A'` or `!A`.

### Outputs

- `truthTable(expr)` → one row per input combination (2^n rows, alphabetical
  variables, first variable = MSB), the minterm numbers where the output is
  1, and every row's input/output values.
- `sopExpression(expr)` (in `kmap.ts`) → canonical SOP, one product term per
  1-minterm, dotless textbook style (`AB' + A'C`); `"0"` when never true,
  `"1"` when always true.
- `toNormalizedString(ast)` → the canonical printout used inside step cards
  (`!` for NOT, `.` for AND, `+` for OR).

## 3. Simplification demo — `src/engines/boolean-simplify.ts`

**Honest scope (spec §16.5):** a *teaching demonstration* of a documented
identity subset — never claimed to be an industrial theorem prover.

### Supported rules (applied in this order until a fixpoint, one rewrite per step)

| Rule | Law |
| --- | --- |
| Double negation | `!!X = X` |
| De Morgan | `!(X.Y) = !X + !Y`  ·  `!(X+Y) = !X.!Y` |
| Identity | `X.1 = X`  ·  `X+0 = X` |
| Domination | `X.0 = 0`  ·  `X+1 = 1` |
| Idempotent | `X.X = X`  ·  `X+X = X` |
| Complement | `X.!X = 0`  ·  `X+!X = 1` |

- Safety cap: `MAX_SIMPLIFY_STEPS = 20` (a `capped` flag reports if it is
  ever reached).
- **Not handled (and not claimed):** absorption (`X + X.Y`), consensus,
  factoring, XOR identities, multi-level restructuring. When no documented
  rule applies the expression is returned unchanged and the UI says why.
- Step record shape: `{ title, before, after, rule, explanation }` — the
  whole expression before and after each single rewrite, plus a
  teacher-voice explanation of the law. The UI additionally verifies the
  simplified result against the original truth table, row by row, and shows
  a match/differ badge.
- `deMorganSteps(expr)` — the De Morgan tab variant: pushes NOTs inward
  using **only** De Morgan + double negation, stopping when no NOT sits
  above an AND/OR.

## 4. Karnaugh maps — `src/engines/kmap.ts`

- **Layouts:** 2 variables → 2×2, 3 → 2×4, 4 → 4×4. First variable(s) ride
  the rows, the rest the columns; both axes are **Gray-coded**
  (`00, 01, 11, 10`) so neighbours differ in exactly one bit.
- **The map is a truth table:** built from the expression's own minterms —
  never a hand-drawn pattern. Random puzzles (`src/lib/kmap-puzzle.ts`) are
  generated by coin-flipping minterms into a real SOP expression (rerolled
  until the map has at least one 1 and one 0).
- **Legal groups:** rectangles of 1, 2, 4, 8, or 16 cells whose rows and
  columns are each contiguous **with wraparound** (edge pairs and the four
  corners count), filled completely, covering only 1-cells.
  `validateGroup(minterms, grid)` returns `{ valid, reason }` with a
  teacher-voice sentence for each way a selection can fail (not a
  power-of-two rectangle, a hole in the rectangle, off-map minterm, empty).
- **Group term** (`groupTerm(grid, rows, cols)`): variables that stay
  constant across the rectangle survive (complemented if their constant is
  0), changing variables drop out; a full-map group is the term `1`.
- **Minimal cover** (`findGroups(grid)`): exact branch-on-first-uncovered-
  cell search over all legal all-ones rectangles — fewest groups first,
  then fewest total literals. ≤ 16 cells, so it is truly minimal, not a
  heuristic.
- **Result:** `resultSop(groups)` ORs the group terms (any `1` group makes
  the whole expression `1`).

### K-map exercise selection rules — `src/lib/kmap-selection.ts`

The board's drag/keyboard selection as pure functions: `cyclicSpan` picks
the shorter cyclic path between two axis positions (wraparound drags select
the edge pair, not the long way round), `rectangleBetween` builds the
rectangle from an anchor cell to the opposite corner, and
`assessStudentGroup` returns one of `duplicate | invalid-shape |
covers-zeros | accepted` — with the engine-labelled product term attached to
an acceptance.

## 5. Number systems — `src/engines/numbers.ts`

Bases: decimal (10), binary (2), octal (8), hexadecimal (16).

### Method selection (by the pair of bases — always the honest textbook route)

| From → To | Method | Step record |
| --- | --- | --- |
| anything → decimal | positional expansion | `{ digit, position, term: "1 × 2^4 = 16", runningTotal }` |
| decimal → anything | division-remainder | `{ dividend, divisor, quotient, remainder }` |
| binary ↔ octal | 3-bit grouping | `{ group: "101", digit: "5" }` |
| binary ↔ hexadecimal | 4-bit grouping | `{ group: "1101", digit: "D" }` |
| octal ↔ hexadecimal | via decimal (positional, then division) | both step lists concatenated |
| same → same | identity | no steps, note "unchanged" |

### Formats and notes the views render

- Division ladder rows display as `25 ÷ 2 = 12 remainder 1`; the closing
  note is `Read the remainders from bottom to top (upward): 11001.`
- Positional rows display as `1 × 2^4 = 16` with `running total 25`.
- Grouping notes state the group size and the padding rule ("groups of 4
  from the right, pad the left with zeros").

### Validation (`validate(text, base)`)

Unsigned whole numbers only. Rejected with a teaching message: signs,
decimal points/commas, digits outside the base (the message names the legal
digit set), more than **16 digits**, and values above **2^53 − 1**
(`Number.MAX_SAFE_INTEGER` — everything stays exact). Leading zeros are
stripped; input is upper-cased (hex `2f` → `2F`).

## 6. Physics — `src/engines/physics.ts`

Every result carries the **formula** and the **numeric substitution** the UI
shows, e.g. `I = 12 V ÷ 4 Ω = 3 A`. All inputs must be non-negative
(friendly `PhysicsError` otherwise).

| Quantity / law | Formula | Substitution format |
| --- | --- | --- |
| Voltage | `V = I × R` | `V = 2 A × 10 Ω = 20 V` |
| Current | `I = V ÷ R` | `I = 12 V ÷ 4 Ω = 3 A` (R = 0 rejected: short circuit) |
| Resistance | `R = V ÷ I` | `R = 12 V ÷ 3 A = 4 Ω` (I = 0 rejected: open circuit) |
| Power (both V,I given) | `P = V × I` | `P = 12 V × 3 A = 36 W` |
| Power (I,R given) | `P = I² × R` | `P = 3² A² × 4 Ω = 36 W` |
| Power (V,R given) | `P = V² ÷ R` | `P = 12² V² ÷ 4 Ω = 36 W` |
| Series resistance | `R = R1 + R2 + …` | `R = 10 + 20 = 30 Ω` |
| Parallel resistance | `R = 1 ÷ (1/R1 + 1/R2 + …)` | `R = 1 ÷ (1/10 + 1/20) = 6.666667 Ω` |

Network analysis (`circuit({ sourceV, resistors, mode })`): equivalent
resistance, total current `I = V ÷ R_eq`, then per resistor —

- series: same current everywhere, `V_k = I × R_k`, `P_k = I² × R_k`
- parallel: same voltage everywhere, `V_k = V_source`, `P_k = V² ÷ R_k`

**Warnings (shown, never hidden):** per-resistor power above **100 W**
(`POWER_WARN_WATTS`) or total current above **10 A**
(`CURRENT_WARN_AMPS`). A 0 Ω parallel branch is rejected as a short
circuit; a 0 Ω equivalent overall is rejected before dividing.

## 7. Circuit builder — `src/engines/circuit.ts`

- **Graph model:** nodes are `input` or `gate` (a gate key from the logic
  engine); each gate has typed input slots holding a source node id or
  `null`. Unwired slots read **0** during evaluation.
- **Operations:** add/remove nodes (removal cleans dangling wires), wire /
  unwire, explicit output list — otherwise gate *sinks* (gates nobody
  consumes) become the truth-table columns.
- **Validation:** cycles are detected (`detectCycle`) and rejected with
  *"Circuits must not feed back into themselves — a combinational circuit
  has no loops."* This is a combinational-only lab by design.
- **Evaluation:** topological order; the whole-circuit truth table is
  offered for **≤ 3 input nodes** (2^n rows, inputs in counting order).
- **Presets** (`PRESETS`, spec §16.3 examples): `A AND B`, `(A OR B) AND C`,
  `A XOR B`, `NOT (A AND B)`.

## 8. Journal — `src/lib/journal.ts` + `src/lib/journal-store.ts`

- zod schemas: stored entries (permissive — it gates corrupt data) and the
  add-form (experiment/module/inputs/prediction/result required;
  observation/conclusion optional, all length-capped).
- Storage: `localStorage` key `logic-science-journal-v1`; corrupt JSON,
  non-arrays, and schema-failing rows are dropped on read — one bad row
  never takes the journal down. Writes go through a small
  `useSyncExternalStore` store so two open tabs stay in sync.
- **CSV export (RFC 4180):** CRLF records; a field containing a comma,
  quote, or newline is quoted and embedded quotes are doubled. Columns:
  `Date, Experiment, Module, Inputs used, My prediction, Actual result,
  Observation, Conclusion`. The UI prefixes a UTF-8 BOM so Excel opens
  UTF-8 correctly (`journalCsv` itself is BOM-free).

## 9. Classroom experiments — `src/lib/classroom-experiments.ts`

Pure data: the eight curated experiments (id, title, objective, module
label, source route, guided step prompts, and a typed stage payload).
`validateRegistry()` self-checks the registry (unique ids, non-empty steps,
internal routes, known gates/bases) and is asserted in the unit tests.
Deep-link parsing: `?e=<id>` finds the experiment, `?step=N` clamps to the
available steps and defaults to 1.
